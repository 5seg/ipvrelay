# タスクC: internal/tui の実装

`internal/tui/tui.go` のスタブを実装せよ。他パッケージは触るな。
依存は `github.com/charmbracelet/bubbletea` と `lipgloss`(既に go.mod にある)。

## 表示するもの (これで全部。増やさない)
- 国 / 都市 / サーバー名(hostname) / RAM 有無 / 負荷 / RTT
- 現在接続中のサーバーとステータス(出口IP、backend 種別、接続数、転送量、エラー)

## 操作
- `↑/↓` または `j/k`: 移動
- `Enter`: 選択中サーバーへ Switch
- `/`: インクリメンタル検索(国・都市・ホスト名にマッチ)
- `r`: RAM-only のみ表示トグル
- `s`: ソート切替(RTT / 負荷 / 国名)
- `q` または Ctrl-C: 終了

## 要件
1. 3秒ごとに `svc.Rows()` と `svc.Status()` を取り直す(`tea.Tick`)。
   `refresh` 引数の間隔を使う。
2. 端末サイズに追従する(`tea.WindowSizeMsg`)。ヘッダ行は固定、リストはスクロール。
3. 選択行を反転表示。`Active` な行は印を付ける(例: `*`)。
4. RTT が -1 のときは `-`、それ以外は `123ms` 表示。負荷は `12%`。
5. RAM-only は `RAM`、通常は空欄。Virtual は `v`、IPv6 は `6` を小さく添える。
6. 検索中はカーソル位置に `/query` を表示し、`Esc` で解除。
7. 起動時に `svc.Switch` を呼ばない。ユーザー操作でのみ切り替える。
8. `Run` は ctx キャンセルで終了し、端末を元に戻す。
9. 色は lipgloss で控えめに。RAM だけ目立たせる程度。
10. 検索・ソート・フィルタのロジックは `tea.Model` の外に出して関数化すると良い。

## 検証
ダミーの `Service` 実装を一時ファイルで書き、`go run` して実際に操作できることを確認せよ。
確認したら一時ファイルは消せ。ヘッドレスでも `Run` がエラーを返さないことを確認すること。
